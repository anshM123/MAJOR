## 3. Inconsistencies found

1. **AG_PROOF §0.1 (row W-χ), §5.2 "Reading", §5.3, §0.2, §8:** "exact scalar ≤ 0.30 S_E over all cutoffs" and the derived "+− margin
   1.35". AG_PROOF had no exact scalar at J = 26–38, so the 0.30 was the J = 64 grid maximum. EDGE_R §4 computes the binding states:
   own-cutoff 0.285 / 0.201 / 0.108 / 0.151 and grid maxima **0.405** / 0.210 / 0.298 / 0.158 at J = 26 / 30 / 34 / 38. So at J = 26 the
   grid maximum touches the tolerance 0.406, and the margin at the tabulated cutoff is 0.406/0.285 = **1.42** (not 1.35). v8 quotes
   EDGE_R.
2. **AG_PROOF "plain envelope, margin ≥ 520"** (§0.2, §5.2, §5.3, §8): EDGE_R §1 shows that the plain tolerance (≥ 158 S_E) and the
   transferred one (≥ 0.406 S_E,t) are the same absolute number (S_E,t/S_E = 408 at (26, 1.026Λ)). The 520 compares the graviton
   tolerance with the *scalar's* edge in plain units and says nothing about the graviton. v8 says so in the Table S9 reading, and the
   paper does not use "plain-envelope J\* = 26" as a graviton statement.
3. **UNIFIED_THEOREM box for AG_PROOF:** it has "tolerance … ≥ 0.406 **S_E** at (26, 1.026Λ)", but AG_PROOF's table has S_E,t (the
   transferred unit). It also has "edge tolerated to 18.9× the scalar envelope", but AG_PROOF §6.2 has "the +− *transferred* scalar
   envelope". v8 uses AG_PROOF's units.
4. **AG_PROOF's own top box (pasted from EDGE_R) vs its body:** the body still says "≤ 0.30 over all cutoffs" and "≥ 520"; only the box
   corrects them. The paper follows the box/EDGE_R.
5. **HK_CLOSE §5 ("every computed per-state value unchanged to ≲ e^{−180} (Q) and ≲ 10⁻⁴¹ (D)") and §6 (row "D cutoff (Λ+100, 10):
   none; worst −19.6 at J = 0")** are false for the literal stored-grid functional at Δ_g = 1000. NU_TAIL_CHECK §4 puts the J = 0 gap
   state's grid tail at ln ≈ +9.8 against −19.6. Both are true for computed values and for the continuum-defined functional. The
   Supplement's v7 wording ("relative effect on any computed number") was correct as far as it went. v8 makes the scope explicit and
   adopts the continuum definition (§S2.B).
6. **`data/README.md` §4 (v4–v7)** defined the functional as the grid sum `Re Σ_k dν X_k …` over the whole stored grid, while the
   Supplement's Table S1 caption already said "the continuum weights are the definitions". This was inconsistent, and harmful at
   Δ_g = 1000 (item 5). Fixed in README §4/§7. `k2/README.md`'s "θ changes nothing computed" is true but silent on the grid floor. It is
   left byte-identical (it is listed in `k2/SHA256SUMS`) and annotated from the main README §6.
